## What this means for the lifter

- Almost everything is Thumb-2 (22,895 functions). The ARM-mode code is 251 functions at 0x53ef68-0x56ad70 (the `_JNIEnv` C++ wrappers and `ALicenseCheck`) plus 23 small ARM helpers and veneers.
- No NEON anywhere and no `.symtab` assembly: the vector unit is used only as VFP (VFPv3 style: `vldr`/`vstr`, `vmov` core<->s/d, `vcvt`, `vcmpe`+`fmstat`, `vsqrt`, `vpush`/`vpop`, `vldmia`/`vstmia`, `fconsts`/`fconstd`). The CPU-feature trick from the playbook (hide NEON in /proc/cpuinfo) is not needed.
- No `.text` relocations; every literal in code is a PC-relative offset, so Thumb PIC code reaches data through `ldr rX, =off; add rX, pc` and the GOT, and function pointers through `.data.rel.ro` (R_ARM_RELATIVE words with the Thumb bit set).
- Jump tables come in four shapes (`Image.jump_tables`): `tbb`, `tbh`, `thumb_word` (`adr; ldr.w rT,[rB,rI,lsl #2]; add rB,rT; bx rB`, entries are offsets from the table address, target = table + word, bit 0 cleared) and one ARM `add pc,pc,rX,lsl #2`.
- Code after a call to a known noreturn import (`abort`, `__cxa_throw`, `pthread_exit`, `__stack_chk_fail`, ...) is not decoded: it is dead code or the literal pool. The only such instance with real instructions in it is the tail of `_Z9threadfunPv` (`movs r0,#0; pop {r4,pc}` after `pthread_exit`).
